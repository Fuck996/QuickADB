# QuickADB 产品与验收约定

## 范围

Windows 便携应用，连接 USB 与同一局域网 Android 设备，以 APK 安装测试为核心。不提供文件浏览、文件传输、投屏、跨互联网远程服务器或源码调试器。

## 抽屉

- 托盘单击展开，点击外部收起，后台任务继续。
- 固定后保持展开，拖动标题区域移动；置顶单独开关。
- 可收成窄栏，再次点击展开。记住固定位置，恢复时限制到有效显示器工作区域。
- 开机启动为用户登录后静默进入托盘，由设置开关控制。
- 关闭窗口收回托盘，退出通过应用菜单；安装进行中退出需要应用内确认。

## 设备与安装

- 简单设备列表直接显示在抽屉，单击选中、再单击取消，无需按 Ctrl。
- 单选和多选使用同一列表；默认不替用户选设备。
- 在线、未授权、离线与断开保持真实区分，设备变化自动更新。
- 没有选中设备时，文件不会开始安装；离线的已保存无线设备可以选择，安装前尝试重连，不自动换到其他设备。
- 拖入或选择 APK 后先检查文件并显示待安装列表；准备阶段无需选设备，不创建任务、不向设备传输。支持清空、移除与更换文件，重新选择或拖入会更换当前待安装列表。
- 检查通过且选中了设备后，用户点击“安装”才创建任务。目标设备绑定点击安装时的选择，之后的选择变更只影响新任务；重复点击同一份待安装内容不会重复提交。每项任务从原设备队列开始执行时获取当前连接，连接期间显示动态状态并可取消，成功后才传 APK；已经开始的传输或 Android 提交不自动重放。
- 拆分 APK 同样先准备，可从“选择拆分 APK”添加，也可在拖入后的列表中明确选择拆分安装；包名、版本、基础包与拆分名检查通过后才能安装。
- 准备检查失败会保留文件和原始原因；后台检查不能恢复已经清空或更换的旧列表。文件在准备后发生变化时，沿用安装链路的文件校验并返回真实失败，不静默改装新内容。
- 拖动鼠标尚未松开、或文件悬停在窗口时，失焦不会收起抽屉。折叠窄栏也接收文件，松开后展开显示待安装列表。
- 同一设备串行安装，不同设备可同时安装。明确显示每项结果。
- 传输按真实字节显示百分比与速度，系统安装使用动态状态，不伪造安装百分比。
- 默认覆盖更新并保留数据；不自动卸载、降级或授予全部运行时权限。
- 失败保留原始错误和中文说明，可单独重试；传输中断或安装结果未知不能表示成功。
- 普通批量 APK 与一个应用的拆分 APK 必须明确区分。

## 无线连接

- Android 11 及以上使用配对码连接。用户先在手机上打开“使用配对码配对设备”，电脑再提交配对码；电脑不能通过连接端口远程打开手机的配对码弹窗。
- USB 与传统 TCP 的 RSA 授权弹窗由连接请求触发，与六位码配对不同。
- 发现列表显示广播型号、服务类型和地址。没有广播型号时明确显示服务名称；授权连接后可使用读取的型号或设备备注。
- 发现列表不以是否已有配对记录或当前连接标签作为显示条件；新设备仅开启无线调试、未打开配对码弹窗时，其连接服务也应可见。服务显示不等于获得授权；点击未配对连接服务只填入 IP 并引导手机配对，不能把连接端口当成配对端口。
- 配对只需手机 IP、配对端口和六位码。连接端口默认通过 mDNS 自动获取；配对服务只填配对端口，不能当作安装连接端口。
- TLS 连接服务的实例名按配对返回的设备 GUID 精确匹配，不用型号或同 IP 猜测设备归属。配对成功后检查已经存在的连接服务；启动时也自动连接发现的已配对设备。
- 配对记录独立保留，即使暂时找不到连接服务仍显示在“已配对设备”。自动发现失败明确提示；用户可展开手动填写无线调试主页中的当前地址和连接端口。传统 TCP 的地址与端口仍为必填。
- 同一已配对设备按 GUID 保持一个身份，地址与端口变化更新原记录。主动断开后不被广播自动重新连接；用户选择连接时再获取当前端口。
- 重启应用后，主设备列表恢复已保存的无线地址及配对记录，保留曾读取的型号、序列号、Android 版本与备注；连接成功前显示真实离线或连接中，默认不选择设备。旧记录没有型号信息时显示原地址或配对标识，成功连接后补齐。
- 意外断线保留无线设备选择，点击安装时按原 GUID 查找当前端口并重连；主动断开仍取消选择。自动发现、手动连接和安装前重连共用连接生命周期，同一设备同时发起的请求等待同一连接，关闭的旧会话不能阻止重连。找不到广播、网络连接失败和授权失败返回真实原因，不移除设备记录。
- 状态检查命令失败不等于整条 ADB 会话断开。检查错误保留在详情与日志，实际断线使用 SDK 的会话关闭通知和原始原因；不重放中断的安装任务。
- 旧版 USB 转无线为明确操作，不自动改变手机的调试配置。
- 设备备注、详情、无线断开与连接记录在管理界面提供。
- 不自动重启或终止其他工具使用的 ADB server。

## 视觉与素材

- 主窗口：标题栏、紧凑设备列表、APK 拖放区、任务列表、状态栏。
- 设备管理：连接记录和设备详情；连接表单使用应用内模态。
- 设置：常驻行为、启动、主题与必要安装选项。
- 空态、加载、禁用、传输中、系统安装中、失败与完成状态均需要清楚呈现。
- EXE 和窗口使用原黑色圆角图标 assets/AppIcon.png。导出时按可见边界去除多余透明留白，生成 AppIconDisplay.png 和包含 16/20/24/32/40/48/64/96/128/256 尺寸的 AppIcon.ico；原图不被替换。
- 托盘独立使用内置 imagegen 绘制的 assets/TrayIcon.png：绿色圆角方形主体，白色向下安装箭头与接收抽屉，外部透明，没有手机轮廓、文字与标语。导出独立 TrayIcon.ico，包含 16/20/24/32 尺寸，每边仅保留约 1 像素安全边距；16 像素资源的可见图形为 14 × 14。
- 两套图标分别嵌入 EXE，托盘通过 Windows LoadIconMetric 按系统小图标尺寸加载 TrayIcon.ico。保留圆角透明，不把原始图片的宽透明边缘一起缩入托盘，不释放图标文件到运行目录。
- 固定窗口使用独立绘制的图钉按钮，悬停提示用途，按下状态表示固定。标题栏拖动和持久化沿用同一行为。

## 交付与证据

- 用户已选择原生单 EXE：不依赖 .NET，不释放应用 EXE/DLL，不依赖外部 adb server。设置、日志与受保护的设备授权数据可以持久保存。
- 验证包括协议集成、设备选择与队列隔离、中文/空格路径、失败与中断、窗口和托盘行为、发布包内容。
- 真机验收包括 USB 授权、无线配对与连接、覆盖安装保留数据、多设备、多 APK、安装失败与连接中断。
- 缺少真机时应保留验收缺口，不能用模拟协议测试宣称真实设备已验证。
