# QuickADB 验证记录

## 0.9.4 设备名称和手工备注持久化

- 排查确认两条代码路径：0.9.3 之前的无线连接只保存地址，手工备注按序列号保存，没有持久化连接记录与型号、序列号的关联；新版信息读取路径又会用空型号覆盖保存值，而当前窗口仍显示旧型号，导致重启后退为地址。本次未读取到用户截图对应的配置，不将代码复现等同于该设备的真机诊断。
- 无线备注使用原设备记录 ID 保存；已配对 TLS 设备的 ID 按 GUID 保持稳定。列表、详情和连接完成使用同一备注读取规则，备注优先于型号；没有序列号的已保存无线设备也可改名。旧版序列号备注在实际连接读到对应身份后自动关联，明确清除备注会阻止旧备注重新出现。USB 备注继续使用序列号，不按相同 IP 猜测手机身份。
- 三项属性的返回结构必须完整，命令失败不能被后续命令的成功掩盖。序列号不符仍拒绝连接；型号和 Android 版本返回合法空值时保留原记录，并在详情与日志暴露缺失信息；返回不完整时不改保存记录、不继续安装。AOSP `getprop` 对未设置属性输出空行并可以返回成功，不能将空值当作新名称。[AOSP getprop 源码](https://raw.githubusercontent.com/aosp-mirror/platform_system_core/master/toolbox/getprop.cpp)。
- 应用集成测试 21 项通过（安装 8、队列 13）。本次新增空型号与版本保留并重新打开磁盘、截断响应保留身份与名字、旧版仅地址配置恢复原备注及清除后重启、无序列号离线配对记录改名后重启。既有身份不符阻止上传、配对 GUID 的端口变化、安装前重连、队列与取消回归保持通过。应用 `clippy --lib --bin QuickADB -- -D warnings`、格式和 diff 检查通过。
- 实际最终 Release 在隔离配置中启动及正式退出后再启动，确认按旧序列号保存的人工名字、缺少型号和序列号但按设备 ID 保存的名字均在主列表可见；详情备注值与列表一致，无序列号离线设备的保存按钮可用。UIAutomation SetValue 未写入文本框，后续原生字符输入也因焦点操作未成功而未完成；未将实际窗口输入并保存新备注标为通过，改名写入与重启依据后台回归测试。
- Release EXE 的文件版本与产品版本均为 0.9.4，15,588,352 字节，21 个导入依赖均为 Windows 系统库，签名状态保持 NotSigned。项目 `artifacts/QuickADB-0.9.4-x64.exe` 与 `U:\开发工作\QuickADB-0.9.4-x64.exe` 的 SHA-256 均为 `7342400867C15B6ECA060B0CED9901054E08459C43EB35E8AF0AC4FE1874DFD0`。
- 旧记录没有保存名称关联时，离线期间不能凭 IP 找回型号或人工备注，需下一次成功连接原手机自动补齐，不要求重新填写备注。本机仍缺少真实 Android 设备，真实设备名称读取、无线恢复和重启验收保留缺口；不修改图标、布局、Windows 防护或发布签名方案。

## 真机验收缺口

0.1.0 验收时用户无法提供真机，本机 ADB 设备列表也没有连接的手机。该阶段以下内容没有用真机验证：USB 驱动与手机授权、Android 无线配对、签名 APK 实际安装、覆盖安装保留数据、各机型安装确认与中断行为。

协议和窗口结果只能证明已覆盖的本地行为，不能据此宣称真实 Android 安装或 USB 驱动兼容性已经通过。拿到设备后，应按 docs/product.md 的真机项目验收。

## 0.1.2 无线端口与会话生命周期修复

- 用户截图中 GT78-VN / Android 12 与 Pocket FIT Elite / Android 16 均为无线离线，安装错误为 `ADB session is closed: session closed locally`。本机应用数据目录只有授权密钥，没有这两台手机的配对记录与错误日志；本次未直接访问这两台真机，不能断言截图中的首次状态检查为何失败。

- 自动连接依据 AOSP 的 `_adb-tls-connect` 服务及配对返回的 GUID 精确匹配。官方源码 `daemon/mdns.cpp` 中连接服务实例名直接使用设备 GUID，不删除 `adb-` 前缀，也不按 IP、型号或配对端口猜测连接归属。配对后检查已存在服务；启动时自动发现已配对设备的当前地址与端口。
