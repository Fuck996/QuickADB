# QuickADB 0.1.0 验证记录

## 本地协议与状态验证

- 应用安装/队列集成测试：10 项通过。
- SDK 配对测试：12 项通过，包含 SPAKE2 协议向量、错误配对码、配对凭据持久化和重新连接的协议夹具。
- 覆盖官方 ABB 参数分隔、实际 APK 字节传输、确认后进度、取消、设备拒绝、最终结果丢失、拆分包会话及清理、旧设备能力分支。
- 两台夹具设备并行传输，同一设备按提交顺序安装。取消设备选择不改变已提交任务的目标。
- 授权私钥以 DPAPI 保护；重新打开数据目录保留同一身份。损坏的设置文件明确失败，不静默重置。
- 安装测试的 APK 是二进制 Manifest/ZIP 夹具，服务端是本地协议夹具，不是 Android 手机或签名发布包。

## 构建与窗口

- 静态 C 运行库构建、Cargo.lock 锁定依赖。
- 原生应用 Clippy 严格检查通过。
- Release 导入表只包含 Windows 系统 DLL，没有外部 ADB、.NET 或应用 DLL。
- Release 已检查静默托盘启动、托盘展开、关闭后继续常驻、再次展开和退出菜单结束进程。
- 设备列表已使用实际应用连接本地协议夹具，检查多选、连接状态、长备注截断。
- 字号、主题、连接弹窗和拖放区按 docs/ui-layout.md 进行最终窗口验收；截图与测量输出保存在忽略的 logs 目录。
- 实际控件测量：两个 APK 操作按钮均为 178 × 40，按钮组居中偏差 0.5，按钮间距 9，提示文字与按钮间距 16 个逻辑像素。
- 样式绑定到应用选定主题，避免启动后的系统主题输入切换到默认字号。辅助文字为 13，实测提示文字高度为 17 个逻辑像素。
- 浅色与深色连接弹窗在淡入动画结束后检查，标签、输入提示、准备说明和操作按钮无重叠；主文字、辅助文字及选中状态分别使用对应主题颜色。

## 真机验收缺口

0.1.0 验收时用户无法提供真机，本机 ADB 设备列表也没有连接的手机。该阶段以下内容没有用真机验证：USB 驱动与手机授权、Android 无线配对、签名 APK 实际安装、覆盖安装保留数据、各机型安装确认与中断行为。

协议和窗口结果只能证明已覆盖的本地行为，不能据此宣称真实 Android 安装或 USB 驱动兼容性已经通过。拿到设备后，应按 docs/product.md 的真机项目验收。

## 发布

发布脚本只复制版本化 EXE，不同步配置、源码、日志或密钥。目标为项目 artifacts 目录和用户指定的 U:\开发工作；复制后检查 SHA-256 一致。构建产物不提交 Git。

## 0.1.1 图标与连接界面

- EXE 和窗口保留原黑色圆角应用图标；托盘单独使用新绘制的绿色安装箭头。原始 PNG 分别归属 AppIcon 和 TrayIcon，不互相替换。
- 两套导出均按 alpha 可见边界裁掉多余透明留白，保留圆角透明；检查所有 ICO 条目的尺寸、透明角和可见边界。16 像素条目两者可见图形均为 14 × 14，托盘 32 像素条目为 30 × 29。
- 应用图标提供 16/20/24/32/40/48/64/96/128/256 条目；托盘提供 16/20/24/32 条目。托盘使用 EXE 内独立资源和 LoadIconMetric，不把整个带宽留白的 PNG 缩入托盘。
- 启动验证发现默认系统 Comctl32 没有 LoadIconMetric 导出；已在内嵌清单声明 Windows Common-Controls 6。修正后实际 Release 正常启动，已有窗口和托盘生命周期未被替换。
- 本机实际托盘截图确认绿色箭头；Windows 将此新图标放在隐藏图标区域，展开后验证，没有修改用户的托盘排列设置。实际截图保存为 logs/tray-0.1.1-actual.png。
- 最终发布 EXE 在隔离的数据目录中验证正式托盘菜单打开、关闭后常驻、再次打开和退出，全部通过。当前验证进程 GetCursorPos 返回拒绝访问（错误 5），托盘库因此不派发鼠标点击回放；没有更改或绕开产品点击逻辑，此次鼠标点击验收须在可读取输入桌面的正常 Windows 会话补验。
- 本机 UIAutomation 验证图钉的取消固定/固定抽屉操作及设置持久化；通过实际应用连接本地协议夹具与 mDNS 广播，不使用另写的界面或假状态。

- 连接弹窗说明手机先打开配对码弹窗；列表区分配对服务、TLS 连接和传统 TCP。内容超出抽屉高度时滚动，修正滚动区初始高度造成的字段裁切；最终窗口截图保存为 logs/connection-0.1.1-final.png。

- 真机验收缺口保持不变：以上无线发现、端口填入和撤销是本地广播夹具；没有据此声称手机授权、真实 Android 配对或 APK 安装已验证。

## 0.1.2 无线端口与会话生命周期修复

- 用户截图中 GT78-VN / Android 12 与 Pocket FIT Elite / Android 16 均为无线离线，安装错误为 `ADB session is closed: session closed locally`。本机应用数据目录只有授权密钥，没有这两台手机的配对记录与错误日志；本次未直接访问这两台真机，不能断言截图中的首次状态检查为何失败。
- 修复前本地复现：只拒绝 `echo quickadb` 的逻辑流，底层 ADB 传输继续可用；应用仍将设备标记离线并主动关闭整条会话。修复后使用 SDK 原有会话状态通知判定真实关闭，检查失败保留详情和日志，设备保持可选择、可安装；真实传输断开及时离线并保留原始原因，不重放安装。
- 自动连接依据 AOSP 的 `_adb-tls-connect` 服务及配对返回的 GUID 精确匹配。官方源码 `daemon/mdns.cpp` 中连接服务实例名直接使用设备 GUID，不删除 `adb-` 前缀，也不按 IP、型号或配对端口猜测连接归属。配对后检查已存在服务；启动时自动发现已配对设备的当前地址与端口。
- 最终应用测试 13 项通过：原有安装测试 8 项、队列/存储与连接测试 5 项。新增检查覆盖 Shell v2、检查命令被拒绝后传输实际 APK 夹具字节并取得成功结果、真实连接丢失、mDNS 自动获取端口、TLS 1.3 / STLS、端口变更后的身份与记录更新、主动断开不被广播连回。自动端口测试预置配对记录，TLS 夹具不检查手机端主机授权，因此不替代 SPAKE2 配对或真机授权验收；配对协议未改动，沿用 0.1.0 的协议夹具记录。
- 修正并发夹具只按 Windows 时间戳命名造成的目录碰撞，加入进程内唯一计数并要求创建新目录；保留测试并发。测试须在可枚举本地网卡、允许 mDNS 的正常 Windows 环境执行，受限进程未收到广播不视为产品验收成功。
- 最终 Release 的实际窗口默认显示手机 IP、配对端口、六位配对码三个输入，可选连接端口默认收起；通过 UIAutomation 验证手动选项展开/收起及已配对页面切换。本地拒绝检查命令的 TLS 设备持续保持在线。窗口截图保存在 `logs/connection-0.1.2-final.png`。
- 当前窗口自动化的 ValuePattern 与定向文本消息均未改变 egui 输入值，因此没有把“不填连接端口点击配对”的按钮输入验收标记为通过。源码已取消必填限制，后台自动发现与安装路径已通过上述集成测试；真实手机配对和输入交互仍须实测。
- 原生 Clippy 严格检查、格式检查和最终 Release 构建通过。发布文件 `QuickADB-0.1.2-x64.exe` 为 15,352,320 字节，导入表只含 21 个 Windows 系统 DLL。项目 artifacts 与 `U:\开发工作` 副本 SHA-256 均为 `975832B323EB5805926E47A95FEBE5CFE415D268AAB5757C8B3292A6B6981F24`。
- 真机验收仍需用户更新后在上述两台 Android 手机上复验无线配对、持续连接、批量安装和实际安装结果。本次没有通过本地协议夹具宣称这两台手机已修复或安装通过。

官方依据：[ADB Wi-Fi 架构](https://android.googlesource.com/platform/packages/modules/adb/+/HEAD/docs/dev/adb_wifi.md)、[adbd 的 mDNS 服务注册](https://android.googlesource.com/platform/packages/modules/adb/+/HEAD/daemon/mdns.cpp)。

## 0.1.3 APK 准备与显式安装

- 选择、上传和拖入 APK 统一进入准备状态，检查文件后才允许点击安装。没有新增“上次 APK”历史功能。提交使用原有安装队列，在点击时绑定选中的在线设备，同设备串行、不同设备并行；重试仍使用原任务目标。
- 应用测试共 15 项通过（安装 8 项、队列/存储/连接 7 项）。新增验证包括准备期间零任务、零传输，无目标设备时保留准备内容，重复点击同一准备版本不重复提交，普通批量与拆分组检查，替换/清空后的旧版本不能提交，以及准备后文件被修改时明确失败而不传输新内容。安装协议未更改，沿用 0.1.0 的配对协议验证记录。
- 文件事件在 `raw_input_hook` 中消费，折叠状态也能接收；拖放悬停或鼠标按下期间延后失焦隐藏。文件选择按钮只记录选择请求，在输入阶段打开系统选择框，避免 UI 多轮布局重复触发阻塞对话框。
- 窗口夹具直接包含正式 `src/native/ui.rs`，使用正式后端、真实 APK 文件和两台本机协议服务。以合成的 egui 文件事件从 440 × 64 折叠窗口展开到 440 × 660，记录 `Ready=true;Jobs=0;Expanded=true`；随后通过实际窗口按钮选择两台设备并点击安装，两台各收到一份 APK，逐字节一致。该夹具没有绕过准备状态或安装队列，也没有预填假任务，但合成输入不等于资源管理器原生拖放。
- 最终窗口检查中文长文件名、准备状态、禁用安装按钮、显式安装成功、原始连接检查提示和底部入口；顶部内容超出空间时局部滚动，任务区独立滚动。底部提示按实际高度预留，滚动区不再受到默认最小高度影响。最终截图为 `logs/preparation-0.1.3-final.png` 与 `logs/install-tasks-0.1.3-final.png`。
- 用户看到的任务栏白色图标来自验收夹具遗漏窗口图标设置；已关闭该窗口并修正夹具。正式应用的 EXE、窗口、标题继续共用原 AppIcon，安装箭头只用于托盘；本次没有重新绘制第三套任务栏图标。
- 原生应用 Clippy 严格检查与格式检查通过。此前打包后发现的任务区布局问题使旧构建失效，修正后重新构建最终 Release。
- 最终 Release EXE 在隔离数据目录中启动，两台协议设备在线，选择 APK 与底部入口可访问；通过正式退出菜单正常结束，退出码为 0，未产生安装传输。文件版本与产品版本均为 0.1.3。
- 发布文件 `QuickADB-0.1.3-x64.exe` 为 15,426,560 字节，导入表只含 21 个 Windows 系统依赖。项目 artifacts 与 `U:\开发工作` 副本 SHA-256 均为 `C946D70164A946ADF7C04D8EEA433383686250AD6A27BC9C8F4E2761C9CA2BB8`。
