# QuickADB

常驻 Windows 托盘的 APK 安装抽屉。使用原生 Rust 应用与静态 ADB 协议库，运行时不释放 adb.exe 或应用 DLL，不要求安装 .NET，也不依赖外部 ADB server。

当前版本：[0.9.6](https://github.com/Fuck996/QuickADB/releases/tag/v0.9.6)，适用于 Windows x64。

许可：[GPL-3.0-only](LICENSE)，来源保留条款见 [NOTICE](NOTICE)。

## 功能

- USB 调试与同一局域网无线配对、自动发现和设备管理。
- 设备单选或多选，保存无线设备、型号和手动备注，安装前自动尝试重连原设备。
- 拖入或选择 APK 后先准备，点击安装才开始；支持单包、普通批量和同一应用的拆分 APK。
- 同一设备串行、不同设备并行，显示真实传输进度及各设备的安装结果。
- 托盘抽屉、图钉固定置顶、拖动定位，以及可调整大小和贴靠的 Windows 标准窗口。
- 可选开机启动、深浅主题；单 EXE 使用，运行依赖静态编译。

0.9.6 将空闲无线断线作为普通离线状态处理，操作提示 8 秒后自动收起，安装按钮保持在可见区域。安装中断仍在对应任务中显示失败或结果未知，原始原因保留在详情与日志。

## 使用

1. USB：手机开启开发者选项和 USB 调试，连接后在手机上允许本机调试。Windows 需有适用于该手机 ADB 接口的驱动。
2. 无线：电脑与手机处于同一局域网，点击“连接设备”。Android 11+ 先在手机上打开“使用配对码配对设备”，再输入手机 IP、六位配对码和配对端口；连接端口默认自动发现，仅发现不可用时手动填写无线调试主页的端口。电脑不能远程触发此配对码弹窗。发现列表显示型号或真实服务名称，点击相应服务可填写对应端口。
3. 点击设备行选择安装目标，再点击取消选择，可选择多台。设备上线不会自动选中。
4. 将一个或多个独立 APK 拖入窗口，或点击“选择 APK”。先检查并显示待安装列表，可以移除、更换或清空文件；准备阶段不会传输或安装。
5. 检查通过后点击“安装到 N 台设备”。任务绑定此时选中的设备，之后改变选择不会转移已有任务。
6. 一个应用的 base/split APK 使用“选择拆分 APK”，一起选入该应用的全部包；也可在准备列表勾选拆分安装。普通批量安装不会把任意多个 APK 当作拆分包。

同一设备按顺序安装，不同设备可以同时安装。传输显示实际确认字节、百分比和速度；Android 执行安装时显示动态状态。最后结果丢失会显示“结果未知”，应先在手机上确认，再决定重试。默认覆盖更新，保留应用数据，不自动卸载或降级。

重启后主列表保留已保存的无线设备及名称、备注。离线无线设备仍可选择；点击安装时先按原设备的配对 GUID 获取当前端口并重连，成功后才传 APK。连接中可以取消，失败保留真实原因与设备记录；不会自动重放已经中断的安装，也不会改装到其他设备。

手动备注优先于手机型号，已保存的无线设备离线时也能改名。旧版仅保存地址和序列号备注的记录，在下一次成功连接原设备后自动补齐名称关联；原备注无需重新输入。手机未返回型号或 Android 版本时保留此前读取的信息，格式异常则明确报错并停止更新。

设备空闲时断线只显示离线，不弹全局断线报错，设备选择、待安装列表和已完成任务保持不变。后台连接检查的临时失败保留在详情及日志。用户操作提示可手动关闭或点击查看完整内容，8 秒后自动收起；任务中的错误和日志不会随提示消失。

托盘单击打开抽屉，点击外部收起；图钉固定后同时保持系统置顶，并可以拖动标题栏放到桌面任意位置。标题区的窗口图标或设置中的“标准窗口模式”可切换为 Windows 原生窗口，支持调整大小、最大化与系统贴靠。标准窗口采用独立设备侧栏、右侧安装包准备区与下方任务表格，设备栏宽度可调整；缩窄时设备选择区可展开，任务改为卡片。窗口模式点击外部保持打开，分别记住窗口大小和位置。未固定时可在设置中单独启用置顶。关闭窗口会隐藏到托盘，退出使用托盘菜单。开机启动需在设置中启用，启动后静默进入托盘。`--tray` 可用于直接启动到托盘。

设置、日志和授权数据保存在 `%LOCALAPPDATA%\QuickADB`。授权私钥使用当前 Windows 账号的 DPAPI 保护，不能直接作为其他账号的授权备份。移动 EXE 后，已启用的开机启动位置会在下一次正常运行时更新。

USB 接口可能被 Android Studio、adb 或其他调试工具占用，应用会显示连接错误，不自动关闭其他程序。驱动与并发访问限制见 [libusb Windows 文档](https://github.com/libusb/libusb/wiki/Windows)。本应用不提供文件传输、投屏或跨互联网远程服务。

## 构建与验证

Windows x64，PowerShell 7，Rust 1.95+，Visual Studio 2022 C++ Build Tools 与 Windows SDK。

```powershell
./scripts/Build.ps1
./scripts/Test.ps1
./scripts/Build.ps1 -Release
```

构建脚本使用项目内忽略的 Cargo 缓存、rsproxy 镜像和静态 C 运行库。版本由 Cargo.toml 与 Cargo.lock 固定。原生 SDK 的来源与修改见 [vendor/README.md](vendor/README.md)。

完成测试、窗口验证和依赖检查后，用 `scripts/Publish.ps1` 生成带版本号的本地产物，并将同版本 EXE 复制到 `U:\开发工作`，校验 SHA-256。输出目录、缓存、日志和授权文件不提交 Git。

发布时同步更新 README 和版本发布说明，先将代码推送到远端并核对提交，再创建对应版本的 GitHub Release，上传已验证的同一份 EXE；版本标签须指向已同步的提交，远端资产须与本地产物校验一致。

0.9.6 已通过 24 项应用协议集成测试和原生窗口、托盘验证，详见 [验证记录](docs/verification.md)。协议夹具通过不代表真实手机通过；USB 授权、手机无线配对、签名 APK 的真实安装和机型驱动兼容性仍需真机验收。

## Windows 发布者提示

当前测试版 EXE 未进行 Authenticode 代码签名。未签名不等于每次启动都会被阻止：SmartScreen 还检查文件信誉，实际启动来源也需要核对。出现“Windows 已保护你的电脑 / 无法识别的应用”时，不能仅凭签名为空判断是唯一原因，也不能据此判断缺少运行依赖。更改版本号、图标或应用清单不能建立发布者信誉。

如需可验证的发布者身份，可使用可信代码签名证书或经过身份验证的签名服务；签名也不保证新文件立即免除 SmartScreen 提示，不能替代对具体被拦截文件的排查。微软说明自签名证书不能解决这种提示，见 [SmartScreen 应用信誉说明](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation)。发布脚本核对 EXE 内部版本，输出实际签名状态与副本 SHA-256，不把未签名文件标记为已认证发布者。
